# Delivery — CAPTURE.WebScraper

How it is built, tested and shipped, and where it lands.

← [Wiki home](../README.md)

| Step | What happens | Automated? |
|---|---|---|
| Build | None for the CLI. `pip install .` builds the `apk_webscraper` package (`pyproject.toml`, setuptools; schema and config ship as package data). Pinned deps: `requirements.txt`. | — |
| Test | `python3 -m pytest -q tests` — 21 tests, all against a local `http.server`; no external request. | By hand before a push (the root's hand-run rule; no workflow here). |
| Run | By hand, on a workstation. Output lands in `scrapes/` beside the code (or `--out`) and is committed here as the intake corpus. | No schedule, no container. |
| Image | The Softapps tree is copied into **WEB.Frontend-Assets** (`Portal-WebStatic`), but the root `.dockerignore` drops `**/scrapes` and `Softapps/**/*.py`, so only `display.json`, the schemas, `config.ini`, the README and the docs land there. Nothing runs in the image. | Copy automatic on `up-stack.sh WEB.Frontend-Assets`. |
| Consumers | CAPTURE.crawler's Web Crawler tab and SCANALYZER Crawler.Like.Audio import `apk_webscraper`. | — |
| Publish | `git push` to <https://github.com/LikeDotAudio/APK.softapp.CAPTURE.WebScraper>; `.apk.scripts/deploy_all.py` pushes every submodule. No public URL. | Run by hand. |
| Smoke | `.apk.scripts/smoke.py` checks HEAD is on origin ([SMOKE](../%F0%9F%A7%A9Manual%20and%20Artifacts/SMOKE.md)). | Run by hand. |

Not automated: the crawl itself, and release tags (Needs owner).

## Delivered from the 2026-10-30 audit
- **robots.txt and per-site rules** — every fetch (page or media) checks the host's own robots.txt through `urllib.robotparser` (RFC 9309: 4xx = no rules, 5xx/unreachable = disallow all; `Crawl-delay` raises the interval), read before any other request to that host. User-Agent, delay, threads, size cap, timeout, `extra_disallow`, `media_hosts`, `keep_query` are `apk_webscraper/config.ini` sections keyed by host. The compiled-in microphone-site `DISALLOWED_PATHS` is gone — it lives on as `[recordinghacks.com] extra_disallow`. Verified: `tests/test_crawl.py` (`/private` disallowed by robots never requested; Crawl-delay; 5xx/4xx; extra_disallow).
- **Media scoped to the target host, host kept in the path** — media is fetched only from the start URL's host or a host the site's config lists in `media_hosts`, and saved as `<folder>-MEDIA/<host>/<path>`, so two hosts' `/logo.png` (and manifests) cannot collide. Verified: `test_media_is_scoped_to_the_target_host_and_keeps_the_host` (second local server never contacted unless listed).
- **One fetch adapter, run state in an object, no prompt** — `Fetcher.fetch()` holds the whole contract (robots, ONE `RateLimiter` per host shared by all workers — the old per-worker sleep let 4 workers hit ~8 req/s —, one timeout, one UA, `read_capped`, manifest via `Fetcher.save()`); `Crawl` holds visited set, queues, locks and scheme (no module globals, two crawls share nothing); `input()` replaced by `--media/--no-media`, plus `--out`, `--config`, `--folder`, `--version`. Code moved into the `apk_webscraper` package; `Scraper.py` is the CLI shim the OS `display.json` still names. Verified: `test_rate_limit_is_per_host_across_all_workers` (14 requests ≥ 1.17 s with 4 workers at 0.1 s), `test_rate_limiter_reserves_one_slot_per_interval_across_threads`, `test_cli_has_no_prompt`, `test_two_crawls_share_no_state`.
- **Tests, schema enforcement, requirements** — `tests/` (21, pytest, local `http.server` fixture: the three-page `/`, `/a`, `/a/b` mirror tree with the manifest migration, size cap, scope, robots, rate, index, CLI, query); `provenance.build()` now validates the full schema (types, `sha256` pattern, status range, `additionalProperties`, `date-time` format) and every sidecar the tests write is also checked with `jsonschema` directly; pinned `requirements.txt` and `pyproject.toml`. Verified: `python3 -m pytest -q tests` → 21 passed; `pip wheel .` builds `apk_webscraper-2.0.0` with schema and config inside.
- **The one crawler** — importable as `apk_webscraper.crawl(url, out, media, config_path, folder, logger, on_file)`; CAPTURE.crawler's Web Crawler tab now calls it (its own downloader/parser deleted, same delivery). SCANALYZER's `Crawler.Like.Audio` now calls it too (SCANALYZER 7d0c59d, from the handoff).
- **Old IS-07 layout retired, provenance backfilled** — the URL-as-path trees `scrapes/is-07/https:/specs.amwa.tv/…` and `scrapes/is-07-MD/…` were folded into `scrapes/specs-amwa-tv-is-07{,-MD}` with `git mv` (history kept): 323 HTML/schema files and 254 Markdown files that only the old crawl had (the newer crawl had stopped at `branches/v1.0.x`) moved across, 22 + 22 byte-identical copies dropped, 26 Markdown files that differed kept in the newer conversion, and two page files that had to become directories moved to `<dir>/index.html` by the scraper's own rule; the old `COMBINED_ARCHIVE` parts were regenerated for the merged tree. Every fetched file in the kept corpora (`microphones` 3,972, `specs-amwa-tv-is-07` 450, `specs-amwa-tv-is-12` 46) now has a `"provenance": "reconstructed"` sidecar (`python3 -m apk_webscraper.backfill`, dated by git's first record of the file, nulls for what was never recorded, a note saying so). `OS/system/pipeline.json`'s path (`scrapes/specs-amwa-tv-is-07`) and LIB.NCP's (`scrapes/specs-amwa-tv-is-12-MD/`) are unchanged. Verified: `tests/test_corpus.py` (old layout gone, every one of the 4,468 manifests validates and names an existing file, no fetched file without one, backfill on a temp git repo).
- **Corpus index and tool version** — `scrapes/INDEX.json` (schema `corpus-index.schema.json`) lists each corpus by folder key and is updated by every run; manifests now carry `fetcher: "Scraper.py 2.0.0"` (`apk_webscraper.__version__`). LIB.NCP now cites the corpus by its index key (LIB.NCP 80717ab); `OS/system/pipeline.json` is still waiting on root/OS (handoff filed); release tags are Needs owner.
- **Query strings documented and configurable** — `normalize_url` still drops the query by default (dedup); a site that paginates by query sets `keep_query = true` and the query becomes part of the filename (`listing@page-2`). Documented in the engine header, README and ARCHITECTURE. Verified: `test_query_dropped_by_default_kept_when_configured`.
- **display.json says what it is** — the generic description replaced. The tool is listed in the OS application walker as a Python CLI.
